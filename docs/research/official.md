# Authoring the instruction layer of coding agents: sourced rules for a linter

Researched 2026-09-27 against the live pages (Claude Code docs as of v2.1.283, published 2026-09-25 on npm). Every quote below was re-read from the page fetched that day; where a figure comes from the Claude Code CHANGELOG, the version and its npm publish date are given. Docs pages were fetched as raw Markdown (`https://code.claude.com/docs/en/<page>.md`, `https://platform.claude.com/docs/en/<page>.md`), so quotes are verbatim.

Legend for each rule: **Applies to** (file types), **Check** (`mech` = deterministic: parse, count, resolve; `llm` = needs judgment), **Sev** (suggested error / warn / info, with the reason). "CC fact" marks how Claude Code loads or costs something; "style" marks writing advice.

## 2. What costs context, and when (Claude Code facts)

These drive "budget" rules. Source: features-overview "Context cost by feature" table and context-window "What survives compaction".

- **CLAUDE.md, CLAUDE.local.md, unscoped `.claude/rules/*.md`, `@path` imports**: full content, every request. features-overview: "CLAUDE.md | Session start | Full content | Every request". Imports do not save context: memory: "Splitting into `@path` imports helps organization but doesn't reduce context, since imported files load at launch."
- **CLAUDE.md is a user message, not system prompt**: memory: "CLAUDE.md content is delivered as a user message after the system prompt, not as part of the system prompt itself."
- **Block-level HTML comments are free**: memory: "Block-level HTML comments (`<!-- maintainer notes -->`) in CLAUDE.md files are stripped before the content is injected into Claude's context." (Comments inside code blocks are kept.) Useful for a linter: do not count them toward size; allow maintainer notes/freshness markers there.
- **Path-scoped rules and nested CLAUDE.md**: load when a matching file is read; after compaction they are summarized away until re-triggered. context-window: "If a rule must persist across compaction, drop the `paths:` frontmatter or move it to the project-root CLAUDE.md."
- **Auto memory**: MEMORY.md first 200 lines/25KB every session; topic files on demand.
- **Skills**: name+description every request for model-invocable skills; body on invocation, then stays in context across turns. `disable-model-invocation: true` removes the description from context entirely ("Description not in context, full skill loads when you invoke"). skills: "Every skill in the skill listing adds to your context on every turn, whether or not Claude ever uses it."
- **Skill body persistence**: skills: "the rendered `SKILL.md` content enters the conversation as a single message and stays there across later turns ... so every line is a recurring token cost."
- **Subagents**: name+description in the main session (warning over 15k tokens combined); body is the subagent's own system prompt and never enters the main context. Subagents receive CLAUDE.md (except Explore/Plan, or `omitClaudeMd: true`), preloaded `skills` in full, git status. They do not receive auto memory or output style.
- **MCP**: with tool search (default) only tool names and server instructions load at start; schemas deferred. costs: "Prefer CLI tools when available ... they don't add any per-tool listing."
- **Hooks**: zero unless they return output. features-overview: "Zero, unless hook returns additional context". Hook output that lands (additionalContext, stdout on SessionStart/UserPromptSubmit, blocking stderr) is capped at 10,000 chars per string.
- **Output styles**: the active style's full text every request (features-overview). A custom style drops the built-in coding instructions unless `keep-coding-instructions: true`.
- **Instructions are not enforcement**: memory: "Claude treats them as context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead." Settings `permissions.deny`, sandbox and hooks are the enforcement layer.

## 3. CLAUDE.md, CLAUDE.local.md, AGENTS.md (always-on instruction files)

Sources: [memory](https://code.claude.com/docs/en/memory), [best-practices](https://code.claude.com/docs/en/best-practices) (the old engineering post `anthropic.com/engineering/claude-code-best-practices` now 308-redirects here), [features-overview](https://code.claude.com/docs/en/features-overview), [costs](https://code.claude.com/docs/en/costs).

- **CM1 Size budget.** Rule: warn when a CLAUDE.md/AGENTS.md/rules file exceeds 200 lines; error above 4 MiB. Quote (memory): "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." and "Claude Code skips a file over 4 MiB." Applies to: CLAUDE.md, CLAUDE.local.md, AGENTS.md, `.claude/rules/*.md`, imported files. Check: mech (count lines after stripping block HTML comments; strip frontmatter for rules). Sev: warn at 200 (documented recommendation, repeated in features-overview and costs); error at 4 MiB (file silently not loaded). Also sum the always-loaded set (root CLAUDE.md chain + unscoped rules + imports) and report it: CC warns on a combined total but does not publish the number, so report info, not error.
- **CM2 Imports resolve.** Rule: every `@path` outside code spans/fences must resolve; flag depth > 4 hops and cycles. Quote: "Relative paths resolve relative to the file containing the import, not the working directory. ... maximum depth of four hops." and "Import parsing skips Markdown code spans and fenced code blocks." Applies to: CLAUDE.md, CLAUDE.local.md, AGENTS.md (CC expands imports in AGENTS.md too), `~/.claude/CLAUDE.md`. Check: mech. Sev: error for unresolved (content the author thinks loads does not); warn for depth > 4 (silently truncated chain). Note `~` expansion and absolute paths are allowed.
- **CM3 External imports need approval.** Rule: info when a project-scope import resolves outside the working directory. Quote: "The first time Claude Code encounters external imports in a project, it shows an approval dialog ... If you decline, the imports stay disabled and the dialog doesn't appear again." Check: mech. Sev: info (works for the author, may be silently off for teammates who declined).
- **CM4 Import vs. prose pointer.** Rule: warn when a CLAUDE.md tells Claude in words to read AGENTS.md (or another file) instead of importing it. Quote: "A `CLAUDE.md` that tells Claude in words to read `AGENTS.md`: Claude sees `AGENTS.md` only if it decides to open the file. ... replace the sentence with an `@AGENTS.md` import." Check: mech (regex for "read/see/follow AGENTS.md" without `@AGENTS.md`), llm to confirm. Sev: warn.
- **CM5 Imports do not reduce context.** Rule: info when a file splits content into imports and total loaded size is large; suggest path-scoped rules or skills instead. Quote: "Splitting into `@path` imports helps organization but doesn't reduce context, since imported files load at launch." Check: mech. Sev: info.
- **CM6 Specific, verifiable instructions.** Rule: flag vague directives ("format code properly", "write clean code", "test your changes"). Quote (memory): "write instructions that are concrete enough to verify ... \"Use 2-space indentation\" instead of \"Format code properly\"". best-practices exclude list: "Self-evident practices like \"write clean code\"". Check: llm (a small mech seed list of stock phrases is possible). Sev: warn.
- **CM7 No contradictions across the loaded set.** Rule: detect conflicting instructions across CLAUDE.md chain, nested CLAUDE.md, rules, user-level rules. Quote: "if two rules contradict each other, Claude may pick one arbitrarily." and (user vs project rules) "if a user rule and a project rule conflict, Claude may follow either one". Check: llm (mech for a few typed facts: package manager, indent width, test command). Sev: warn.
- **CM8 Exclude derivable content.** Rule: flag directory trees, file-by-file descriptions, dependency lists, long tutorials, standard language conventions, full API docs. Quote (best-practices table, Exclude column): "Anything Claude can figure out by reading code", "File-by-file descriptions of the codebase", "Long explanations or tutorials", "Detailed API documentation (link to docs instead)". memory: `/doctor` "cuts content Claude can derive from the codebase, such as directory layouts, dependency lists, and architecture overviews, and keeps pitfalls, rationale, and conventions that differ from tool defaults." Independent evidence: Gloaguen et al. 2026 ([arXiv 2602.11988](https://arxiv.org/abs/2602.11988)) found repository overviews "are not helpful" and context files raise cost over 20%. Check: mech for large tree blocks/long dependency tables; llm otherwise. Sev: warn.
- **CM9 Procedures and area-specific content belong elsewhere.** Rule: flag multi-step procedures (numbered runbooks) and area-specific sections in CLAUDE.md; suggest a skill or a `paths`-scoped rule. Quote (memory): "If an entry is a multi-step procedure or only matters for one part of the codebase, move it to a skill or a path-scoped rule instead." costs: "If it contains detailed instructions for specific workflows (like PR reviews or database migrations), those tokens are present even when you're doing unrelated work." Check: llm (mech heuristic: an ordered list of 8+ steps under one heading, or a heading naming a subdirectory). Sev: info.
- **CM10 Must-happen rules belong in hooks/permissions.** Rule: flag "always run X before commit / after each edit" and "never touch .env" style rules and suggest a hook or deny rule. Quote (memory): "If the instruction is something that must run at a specific point, such as before every commit or after each file edit, write it as a hook instead." features-overview: "An instruction like \"never edit `.env`\" in CLAUDE.md or a skill is a request, not a guarantee." Check: llm (mech regex seed: "before (every )?commit", "after (each|every) edit", "never (edit|read|touch)"). Sev: info (advice, not a defect).
- **CM11 Emphasis budget.** Rule: warn when many lines carry emphasis markers (IMPORTANT, CRITICAL, MUST, NEVER, ALL-CAPS, bold). Quote (best-practices): "If Claude keeps skipping one instruction, add emphasis such as \"IMPORTANT\" to that line alone. If you emphasize many lines, none of them stands out." Prompting guide: "The fix is to dial back any aggressive language. Where you might have said \"CRITICAL: You MUST use this tool when...\", you can use more normal prompting like \"Use this tool when...\"." Check: mech (ratio of emphasized lines; count of all-caps imperative tokens). Sev: warn above a ratio (the docs give no number; pick a default such as more than 3 emphasized lines or more than 5% of lines and document it as the tool's own threshold).
- **CM12 Structure.** Rule: info when a long file has no headings/bullets (dense paragraphs). Quote: "use markdown headers and bullets to group related instructions. Claude scans structure the same way readers do". Check: mech. Sev: info.
- **CM13 CLAUDE.local.md hygiene.** Rule: warn when CLAUDE.local.md is tracked by git. Quote: "Add `CLAUDE.local.md` to your `.gitignore` so it isn't committed." Check: mech (`git ls-files`). Sev: warn.
- **CM14 CLAUDE.local.md suppresses AGENTS.md.** Rule: info when a repo relies on AGENTS.md (no CLAUDE.md) but a CLAUDE.local.md exists on the path. Quote: "Because `CLAUDE.local.md` counts, adding one ... stops Claude from reading `AGENTS.md` for you." Check: mech. Sev: warn (AGENTS.md content silently dropped under the default `claude-md-or-agents-md`).
- **CM15 AGENTS.md vs CLAUDE.md coexistence.** Rule: when both exist on the path and CLAUDE.md does not import AGENTS.md, warn that CC reads only CLAUDE.md by default. Quote: "An `AGENTS.md` and a `CLAUDE.md` or `CLAUDE.local.md` in your working directory or above it | Your `CLAUDE.md` files only". Check: mech. Sev: warn. (AGENTS.md direct read requires CC v2.1.277, 2026-09-18; before that only an import worked.)
- **CM16 Files Claude Code never reads.** Rule: info for `AGENTS.local.md`, `AGENTS.override.md`, `.agents/` when the target is Claude Code. Quote: "Not read: `AGENTS.local.md`, `AGENTS.override.md`, or anything under a `.agents/` directory". Codex does read `AGENTS.override.md`. Check: mech. Sev: info.
- **CM17 Duplicate loading.** Rule: warn when a SessionStart hook prints AGENTS.md/CLAUDE.md content that CC already loads. Quote: "A `SessionStart` hook that prints `AGENTS.md`: remove it. Once Claude reads `AGENTS.md` directly, the hook adds a second copy to the context." Check: mech (hook command cat/Get-Content of an instruction file). Sev: warn.
- **CM18 Symlinked CLAUDE.md on Windows.** Rule: info when CLAUDE.md is a symlink to AGENTS.md in a repo that may be cloned on Windows. Quote: "Git checks a committed symlink out as a plain text file unless `core.symlinks` is enabled, which leaves that clone with a one-line `CLAUDE.md` in place of your instructions". Check: mech (git mode 120000). Sev: info.
- **CM19 Symlinks to network paths do not load.** Quote: "If you point a `.claude/rules/` or `CLAUDE.md` symlink at a network path such as the UNC share `\\server\share` ... the linked instructions don't load." Check: mech. Sev: error.
- **CM20 Keep only what would cause mistakes if removed.** Quote (best-practices): "For each line, ask: \"Would removing this cause Claude to make mistakes?\" If not, cut it. Bloated CLAUDE.md files cause Claude to ignore your actual instructions!" Check: llm. Sev: info. Style.
- **CM21 Personal vs team scope.** Rule: flag personal preferences (editor, sandbox URLs, "my" tooling) in the committed project CLAUDE.md. Quote (memory): "focus on project-level standards rather than personal preferences"; the Local instructions row lists "Your sandbox URLs, preferred test data". Check: llm. Sev: info.
- **AGENTS.md spec (agents.md), secondary.** No required fields: "No. AGENTS.md is just standard Markdown." Suggested sections: "Project overview, Build and test commands, Code style guidelines, Testing instructions, Security considerations". Conflict rule: "The closest AGENTS.md to the edited file wins; explicit user chat prompts override everything." (See disagreements, section 14.) Codex: files concatenated root-down, one per directory, override wins within a directory, 32 KiB combined cap, empty files skipped. A linter targeting Codex should warn when the concatenated chain exceeds 32 KiB (content past it is dropped).

## 4. `.claude/rules/*.md` (and `~/.claude/rules/`)

Source: [memory, "Organize rules with .claude/rules/"](https://code.claude.com/docs/en/memory).

- **RL1 Only `paths` is read.** Quote: "`paths` is the only field Claude Code reads from a rule; any other field is ignored without an error." Check: mech. Sev: warn on unknown keys (e.g. Cursor-style `globs`, `alwaysApply`, `description`), because the author likely expects them to scope the rule and it now loads unconditionally.
- **RL2 Frontmatter must parse.** Quote: "If the YAML between the markers doesn't parse, Claude Code ignores the frontmatter and loads the rule as if it had no `paths`." Check: mech. Sev: error (a scoped rule silently becomes always-on).
- **RL3 Valid globs.** Quote: "A pattern with a `[` that can't be read as a bracket expression, such as `photos [2024/**`, is invalid: it matches nothing". Brace budget 1,000 patterns / 4 MiB, over which "its literal braces match no files." Check: mech. Sev: error for invalid or over-budget patterns; warn for patterns that match no file in the repo (dead rule).
- **RL4 Unscoped rule = CLAUDE.md content.** Quote: "Rules without a `paths` field are loaded unconditionally". Steering blog: "An unscoped rule is mechanically identical to putting the content in CLAUDE.md: always loaded, always costing tokens." Check: mech (count into the always-loaded budget of CM1). Sev: info; llm to suggest a scope when the text names a directory or language.
- **RL5 One topic per file, descriptive filename.** Quote: "Each file should cover one topic, with a descriptive filename like `testing.md` or `api-design.md`." Check: llm (mech: flag generic names like `rules.md`, `misc.md`, `notes.md`). Sev: info.
- **RL6 Rules that must survive compaction.** Quote (context-window): "If a rule must persist across compaction, drop the `paths:` frontmatter or move it to the project-root CLAUDE.md." Check: llm. Sev: info.
- **RL7 Symlinked rules outside the project.** Quote: "The linked rules don't load until you approve external imports for the project, and after that only the ones without a `paths` field load." Check: mech. Sev: warn for a `paths`-scoped rule reached through an external symlink (never loads).

## 5. Auto memory (`~/.claude/projects/<project>/memory/`) and memory files

Source: [memory, "Auto memory"](https://code.claude.com/docs/en/memory).

- **MM1 MEMORY.md within limits.** Quote: "The first 200 lines of `MEMORY.md`, or the first 25KB, whichever comes first, are loaded ... Content beyond that threshold is not loaded at session start." Check: mech. Sev: error over either limit (entries past it are invisible); warn near it (for example 90%).
- **MM2 Index shape.** Quote: "keep one line per entry, move detail into topic files, and merge or drop stale entries." Check: mech (multi-line entries, lines with no link to a topic file). Sev: info.
- **MM3 Index links resolve; orphan topic files.** Topic files load on demand via MEMORY.md ("Claude reads them on demand using its standard file tools"). Check: mech (links in MEMORY.md exist; topic files not referenced from MEMORY.md are unreachable). Sev: warn for broken links; info for orphans.
- **MM4 Frontmatter `type` values.** Documented kinds: `user`, `feedback`, `project`, `reference`; CC adds a `modified` ISO 8601 field on write to files that already have frontmatter (v2.1.214+). Check: mech. Sev: info for unknown `type`.
- **MM5 Do not duplicate CLAUDE.md or derivable facts.** Quote: "Claude skips anything it can derive from the codebase, such as architecture, file paths, or debugging fixes. It also skips anything your CLAUDE.md files already say." Check: mech for exact/near-duplicate lines vs CLAUDE.md; llm for derivable content. Sev: info.
- **MM6 Subagent memory dirs.** `memory: user|project|local` maps to `~/.claude/agent-memory/<name>/`, `.claude/agent-memory/<name>/`, `.claude/agent-memory-local/<name>/`. Check: mech (the `local` directory should be gitignored). Sev: info.

## 6. Skills (`SKILL.md`) and legacy commands (`.claude/commands/*.md`)

Sources: [Claude Code skills](https://code.claude.com/docs/en/skills), [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices), [Agent Skills spec](https://agentskills.io/specification), [Equipping agents ... with Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills) (2025-10-16), Anthropic PDF "The Complete Guide to Building Skills for Claude" (PDF metadata date 2026-01-26).

Recognized frontmatter keys in Claude Code: `name`, `description`, `when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `model`, `effort`, `context`, `agent`, `background`, `hooks`, `paths`, `shell`, `metadata`, `license`, `compatibility`. Command files accept the same "except `name` and `paths`". Booleans accept `yes/no/on/off/1/0` (v2.1.218+).

- **SK1 Frontmatter placement and parse.** Quote: "Claude Code reads the frontmatter only when the opening `---` is the file's first line. Otherwise it treats the whole file, `---` markers included, as skill content. If the YAML between the markers doesn't parse, the skill still loads with no fields set". Troubleshooting: "Claude can't match against your `description`." Check: mech. Sev: error (auto-invocation silently broken). Official check exists: `claude plugin validate .claude/skills` (v2.1.233+).
- **SK2 Unknown keys.** Quote: "A field name must match the table exactly, hyphens included: Claude Code ignores a field it doesn't recognize without reporting an error." Check: mech (also catch snake/camel variants such as `allowed_tools`, `disableModelInvocation`; `when_to_use` is the one underscore key). Sev: warn.
- **SK3 Portability profile.** Rule: when the skill is meant for claude.ai/API/other agents, only the six spec keys are allowed. Quote: "Unexpected key(s) in SKILL.md frontmatter: argument-hint. Allowed properties are: allowed-tools, compatibility, description, license, metadata, name". Check: mech. Sev: error in a "portable" profile, off by default for Claude Code-only skills.
- **SK4 `description` present and front-loaded.** Quote: "Only `description` is recommended so Claude knows when to use the skill. ... Put the key use case first: the combined `description` and `when_to_use` text is truncated at 1,536 characters". Without it CC uses "the first non-empty line of the markdown content". Check: mech. Sev: warn if missing (CC); error if missing in the portable profile (spec: required); warn if combined length > 1,536 (truncated in CC); error if description > 1,024 in the portable profile.
- **SK5 Description says what and when.** Quote (platform): "The `description` field enables Skill discovery and should include both what the Skill does and when to use it." and "Avoid vague descriptions like these: ... Helps with documents". Check: llm (mech heuristic: presence of a trigger clause such as "Use when"/"when the user"). Sev: warn.
- **SK6 Third person.** Quote (platform): "Always write in third person. The description is injected into the system prompt, and inconsistent point-of-view can cause discovery problems." Check: mech (first/second-person pronouns at the start: "I can", "You can", "I will"). Sev: warn. (Platform doc only; the Claude Code skills page is silent. Note the platform says "system prompt" while CC delivers the listing as its own mechanism; the advice still applies.)
- **SK7 No XML tags in name/description.** Quote (platform): "Cannot contain XML tags". PDF guide: "Forbidden in frontmatter: XML angle brackets (< >) ... Why: Frontmatter appears in Claude's system prompt. Malicious content could inject instructions." Check: mech. Sev: error in the portable profile; warn in CC.
- **SK8 Name rules.** Spec: 1-64 chars, lowercase alphanumerics and hyphens, no leading/trailing/consecutive hyphens, "Must match the parent directory name"; reserved words "anthropic", "claude". Claude Code: `name` is optional (defaults to directory name) and the directory name also invokes it. Check: mech. Sev: error in portable profile; in CC, warn for mismatch with directory name (two command names for one skill, confusing) and for reserved words. Naming style ("gerund form", avoid `helper`, `utils`) is advice: info.
- **SK9 Body size.** Quote (CC tip and platform): "Keep `SKILL.md` under 500 lines. Move detailed reference material to separate files." Check: mech. Sev: warn over 500 lines. Optionally warn over 5,000 tokens (spec: "< 5000 tokens recommended"). Also: context-window notes truncation after compaction keeps the start of the file, "so put the most important instructions near the top of `SKILL.md`" (llm, info).
- **SK10 Concise body, no restating what Claude knows.** Quote (CC): "Keep the body itself concise. Once a skill loads, its content stays in context across turns, so every line is a recurring token cost. State what to do rather than narrating how or why". Platform: "Only add context Claude doesn't already have." Check: llm. Sev: info. (Tension with "explain why", see section 14.)
- **SK11 Supporting files referenced, and one level deep.** Quote (platform): "Keep references one level deep from SKILL.md. All reference files should link directly from SKILL.md". CC: "Reference supporting files from `SKILL.md` so Claude knows what each file contains and when to load it". Check: mech (every link in SKILL.md resolves inside the skill dir; referenced .md files that themselves link to further bundled .md files; bundled files never referenced from SKILL.md). ## 8. Hooks (settings `hooks`, plugin `hooks/hooks.json`, skill/agent frontmatter `hooks`)

Source: [hooks reference](https://code.claude.com/docs/en/hooks), [hooks-guide](https://code.claude.com/docs/en/hooks-guide).

Valid event names (headings of the hooks reference, 2026-09-27): SessionStart, Setup, InstructionsLoaded, UserPromptSubmit, UserPromptExpansion, MessageDisplay, PreToolUse, PermissionRequest, PostToolUse, PostToolUseFailure, PostToolBatch, PermissionDenied, Notification, SubagentStart, SubagentStop, TaskCreated, TaskCompleted, Stop, StopFailure, TeammateIdle, ConfigChange, CwdChanged, DirectoryAdded, FileChanged, WorktreeCreate, WorktreeRemove, PreCompact, PostCompact, PreModelSwitch, PostModelSwitch, SessionEnd, Elicitation, ElicitationResult. Handler `type`: `command`, `http`, `mcp_tool`, `prompt`, `agent`. Subagent frontmatter hooks: `PreToolUse`, `PostToolUse`, `Stop` (converted to SubagentStop).

- **HK1 Unknown event names are dropped.** Quote (settings): "Settings Warning: only individual entries fail, such as a malformed permission rule or an unknown hook event name. Claude Code skips those values". Check: mech (case-sensitive match against the list). Sev: error (the hook never runs).
- **HK2 Handler shape.** Required `type`; command needs `command`; prompt/agent need a prompt. Check: mech (JSON schema: `https://json.schemastore.org/claude-code-settings.json`). Sev: error.
- **HK3 MCP matchers need `.*`.** Quote: "The `.*` is required: a matcher like `mcp__memory` or `mcp__brave-search` contains only exact-match characters, so it is compared as an exact string and matches no tool." Check: mech. Sev: error. (Contrast: in permission rules `mcp__puppeteer` does match every tool of the server; the linter must apply different grammars.)
- **HK4 Regex matchers are unanchored.** Quote: "`Edit.*` matches both `Edit` and `NotebookEdit`; wrap the pattern in `^` and `$` ... when you need a whole-string match." Check: mech (regex-path matchers that are prefixes of other tool names). Sev: warn. Also: `FileChanged` and `StopFailure` exact-match set excludes `-`, space, `,`.
- **HK5 `if` only on tool events; one rule only.** Quote: "Only evaluated on tool events: `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionRequest`, and `PermissionDenied`. On other events, a hook with `if` set never runs." and "There is no `&&`, `||`, or list syntax". Check: mech. Sev: error.
- **HK6 `once` only in skill frontmatter.** Quote: "Only honored for hooks declared in skill frontmatter; ignored in settings files and agent frontmatter". Check: mech. Sev: warn.
- **HK7 Blocking needs exit 2 (or JSON), not exit 1.** Quote: "Without valid JSON on stdout, Claude Code treats exit code 1 as a non-blocking error and proceeds with the action ... If your hook is meant to enforce a policy, use `exit 2`." `PermissionRequest` ignores exit 2. Check: mech for inline commands and scripts (`exit 1` in a PreToolUse script with no `exit 2`); llm to judge intent. Sev: warn.
- **HK8 Script path must exist and be executable.** Quote: "a mistyped path in `settings.json` leaves the gate silently disabled." Check: mech (resolve `${CLAUDE_PROJECT_DIR}`, `${CLAUDE_PLUGIN_ROOT}`; exec bit on POSIX). Sev: error.
- **HK9 Absolute/placeholder paths and quoting.** Quote (security best practices): "Always quote shell variables: use `\"$VAR\"` not `$VAR`", "Use absolute paths: ... In exec form, use `${CLAUDE_PROJECT_DIR}` ... In shell form, wrap it in double quotes"; "Prefer exec form for any hook that references a path placeholder." Check: mech (unquoted placeholders in shell form; relative script paths). Sev: warn.
- **HK10 Exec form sanity.** Quote: "If `command` is a bare name with no path separator and contains whitespace alongside `args`, Claude Code logs a warning because the spawn will fail". Check: mech. Sev: error.
- **HK11 Output size.** Keep `additionalContext`/stdout under 10,000 chars; "Claude Code doesn't ask Claude to read the file, so keep anything Claude must always see within the cap." Check: static only for literal strings; otherwise info. Sev: info. Also CC fact: hook-injected context costs tokens each time it fires (SessionStart, UserPromptSubmit additionalContext).
- **HK12 stdout must be only JSON when using JSON output.** Quote: "Your hook's stdout must contain only the JSON object. If your shell profile prints text on startup, it can interfere with JSON parsing." Check: llm/heuristic (echo statements before JSON). Sev: info.
- **HK13 Timeouts.** UserPromptSubmit default 30 s and "a stuck hook stalls the session"; SessionEnd shares a 1.5 s budget. Check: mech (explicit `timeout` far above defaults on UserPromptSubmit/SessionEnd; `timeout` on `async: true`, which is not enforced). Sev: info.
- **HK14 Hook decisions don't override deny/ask rules.** Quote (permissions): "Hook decisions don't bypass permission rules. ... a matching deny rule blocks the call, and a matching ask rule still prompts even when the hook returned \"allow\"". Check: mech (PreToolUse hooks whose purpose is to allow a tool that a deny rule covers). Sev: info.
- **HK15 Trust.** Quote: "`-p` or SDK session: Claude Code never shows the dialog and treats the folder as trusted, so hooks committed in a repository's `.claude/settings.json` run in a folder you've never trusted". Check: mech (report every project-scope command hook as an audit list). Sev: info. Also "Command hooks execute shell commands with your full user permissions."
- **HK16 HTTP hooks.** `allowedHttpHookUrls` and `httpHookAllowedEnvVars` restrict URL and header env interpolation. Check: mech (http hooks with env vars in headers and no allowlist). Sev: info.

## 9. Settings and permissions (`.claude/settings.json`, `.claude/settings.local.json`, `~/.claude/settings.json`, managed)

Sources: [settings](https://code.claude.com/docs/en/settings), [permissions](https://code.claude.com/docs/en/permissions), [settings-reference](https://code.claude.com/docs/en/settings-reference).

- **ST1 Schema-valid JSON.** Quote: "The `$schema` line points to the published JSON schema ... which gives you autocomplete and inline validation". Invalid JSON: "Settings Error ... continue without the broken settings." Check: mech (validate against `https://json.schemastore.org/claude-code-settings.json`; warn when `$schema` is absent). Sev: error for invalid JSON or schema-rejected values; info for missing `$schema`.
- **ST2 Evaluation order is deny, ask, allow.** Quote: "Rules are evaluated in order: deny, then ask, then allow. The first match in that order determines the outcome, and rule specificity doesn't change the order." and "An allow rule can't carve an exception out of a deny rule." Across scopes: "a user-level deny blocks a project-level allow". Check: mech (allow rules fully shadowed by a deny/ask rule in any loaded scope are dead). Sev: warn.
- **ST3 Path rules only on Read/Edit.** Quote: "If you write a path rule for `Write`, `NotebookEdit`, `Glob`, or the legacy `MultiEdit` tool instead, Claude Code accepts the rule but never consults it". Check: mech. Sev: error (a deny that does nothing).
- **ST4 Read/Edit deny limits.** Quote: deny rules apply to built-in tools and recognized Bash file commands but "don't apply to a command that reads files without naming them, such as `grep -r pattern .` ... or to arbitrary subprocesses". "For OS-level enforcement ... enable the sandbox." Check: mech (secret-path deny rules without `sandbox.enabled`). Sev: info.
- **ST5 Deny secret paths.** Quote: "To block Claude's file tools from reading a file or directory, add a `Read` deny rule for its path, such as `Read(./.env)` or `Read(./secrets/**)`". Check: mech (repo contains `.env*`, `*.pem`, `id_rsa` etc. and no matching Read deny). Sev: warn.
- **ST6 Bash wildcard grammar.** Quote: "The space before a trailing `*` is part of the rule. `Bash(ls *)` requires a space after `ls`, so `lsof` doesn't match. `Bash(ls*)` has no space, so it matches `lsof` too." and "The `:*` form is only recognized at the end of a pattern. In a pattern like `Bash(git:* push)`, the colon is treated as a literal character". Check: mech. Sev: warn for no-space prefix wildcards in allow rules; error for mid-pattern `:*`.
- **ST7 Argument-constraining Bash rules are fragile.** Quote: "Bash permission patterns that try to constrain command arguments are fragile." (curl URL example). Check: mech (deny/allow rules that pin URLs or flags). Sev: info, suggest WebFetch domain rules, sandbox network allowlist, or a PreToolUse hook.
- **ST8 WebFetch domain rules.** `WebFetch(domain:*.example.com)` "but not `example.com` itself"; bare `WebFetch` and `WebFetch(domain:*)` differ for sandbox propagation. Check: mech (allow `*.x.com` without `x.com`). Sev: info.
- **ST9 MCP permission ids.** `mcp__server`, `mcp__server__*`, `mcp__server__tool`; server must exist. Check: mech. Sev: warn for unknown servers.
- **ST10 Managed-only keys.** Some keys are honored only in managed/policy settings, e.g. `claudeMd` ("Setting `claudeMd` in user, project, or local settings has no effect"); `pluginConfigs` for `agents-md@builtin` is ignored in project/local. Check: mech against a key-scope table. Sev: warn.
- **ST11 Project settings that need trust.** Hooks, `autoMemoryDirectory` etc. in repo settings follow workspace trust; `.mcp.json` approvals can't be self-granted by a cloned repo ("A cloned repository can't approve its own servers"). Check: mech (`enableAllProjectMcpServers: true` in a committed `.claude/settings.json`). Sev: warn.
- **ST12 settings.local.json is personal.** Check: mech (tracked in git). Sev: warn.
- **ST13 `claudeMdExcludes` matches absolute paths.** Quote: "Patterns are matched against absolute file paths using glob syntax." Check: mech (relative patterns without `**/` prefix never match). Sev: warn.

## 13. Cross-cutting prompt-writing rules (apply to the prose of every instruction file)

Sources: [Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) (covers models through Claude Opus 5.5 / Fable 5.1 as of 2026-09-27), model pages ([Sonnet 5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5), [Opus 4.8](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-4-8), [Fable 5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5)), [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (2025-09-29).

- **PR1 Be clear and direct.** Quote: "Claude responds well to clear, explicit instructions." "Golden rule: Show your prompt to a colleague with minimal context on the task and ask them to follow it. If they'd be confused, Claude will be too." Check: llm. Sev: info.
- **PR2 Explain why for non-obvious rules.** Quote: "Providing context or motivation behind your instructions, such as explaining to Claude why such behavior is important, can help Claude better understand your goals" (example: "NEVER use ellipses" vs the text-to-speech reason). "Claude is smart enough to generalize from the explanation." Steering blog: "explaining the why behind constraints". Check: llm (flag bare prohibitions, especially emphasized ones, with no reason). Sev: info. Tension with SK10 "rather than narrating how or why" (section 14).
- **PR3 Positive framing.** Quote: "Tell Claude what to do instead of what not to do" (in the output-format section). Check: llm (mech: ratio of "don't/never/avoid" lines). Sev: info. Scope note: the doc states this for output formatting; applying it to all rules is an extrapolation.
- **PR4 Dial back aggressive emphasis on current models.** Quote: "Claude Opus 4.5 and Claude Opus 4.6 are also more responsive to the system prompt than previous models. If your prompts were designed to reduce undertriggering on tools or skills, these models may now overtrigger. The fix is to dial back any aggressive language." Also: "Instructions like \"If in doubt, use [tool]\" will cause overtriggering." Check: mech (CRITICAL/MUST/ALWAYS/"if in doubt" density) plus llm. Sev: warn. Fable 5: "Skills developed for prior models are often too prescriptive for Claude Fable 5 and can degrade output quality."
- **PR5 State scope explicitly (literal instruction following).** Quote (Sonnet 5 and Opus 4.8 pages): "It does not silently generalize an instruction from one item to another ... If you need Claude to apply an instruction broadly, state the scope explicitly". Check: llm. Sev: info.
- **PR6 Examples: few, diverse, tagged.** Quote: "Wrap examples in `<example>` tags ... Include 3–5 examples for best results." Context engineering: "teams will often stuff a laundry list of edge cases into a prompt ... We do not recommend this. Instead, ... curate a set of diverse, canonical examples". Check: mech (count of example blocks; untagged examples mixed with instructions); llm. Sev: info.
- **PR7 XML tags or headers for mixed content.** Quote: "XML tags help Claude parse complex prompts unambiguously ... Use consistent, descriptive tag names". Context engineering: "the exact formatting of prompts is likely becoming less important as models become more capable." Check: mech (unbalanced or inconsistently named tags). Sev: warn for unbalanced tags; info otherwise.
- **PR8 Right altitude.** Quote (context engineering): "At one extreme, we see engineers hardcoding complex, brittle logic in their prompts ... At the other extreme, engineers sometimes provide vague, high-level guidance". Platform skills: "Match the level of specificity to the task's fragility and variability." Check: llm. Sev: info.
- **PR9 Minimal high-signal set.** Quote: "find the smallest possible set of high-signal tokens that maximize the likelihood of some desired outcome." "(Note that minimal does not necessarily mean short ...)". Check: llm. Sev: info.
- **PR10 Don't ask the model to reproduce its reasoning (Fable 5 / Mythos 5).** Quote: "Prompts, skills, or harness instructions that tell the model to echo, transcribe, or explain its internal reasoning as response text can trigger the `reasoning_extraction` refusal category ... Audit existing skills and system prompts for reflection or show-your-thinking instructions when migrating." Check: mech seed ("show your reasoning", "explain your thinking step by step in the response", "transcribe your thoughts") plus llm. Sev: warn when the configured model family is Fable/Mythos 5+, info otherwise. New in 2026; model-specific.
- **PR11 Don't surface context-budget countdowns (Fable 5).** Quote: "Avoid surfacing explicit context-budget counts where possible." Relevant to hooks/statusline text injected into context. Check: llm. Sev: info.

## 14. Where sources disagree (flag, don't pick silently)

- **14.1 Skill `name`/`description` required?** Claude Code: "All fields are optional. Only `description` is recommended". Platform and spec: both required. Resolution: profile-dependent severity (SK4, SK8).
- **14.2 Description length.** Spec/platform/PDF: 1,024 max. Claude Code: listing truncates `description`+`when_to_use` at 1,536 (raised from 250 in v2.1.105, 2026-04-13; the 250 cap arrived in v2.1.86, 2026-03-27). A description of 1,025-1,536 chars works in CC and fails upload elsewhere.
- **14.3 SKILL.md body size.** 500 lines (CC, platform, spec) vs "< 5000 tokens recommended" (spec) vs "under 5,000 words" (Anthropic PDF, 2026-01-26). The three are not equivalent; use 500 lines as the primary check.
- **14.4 Emphasis.** Prompting guide says dial back "CRITICAL: You MUST"; CC best-practices allows emphasis on a single ignored line; the platform skill guide's iteration example suggests "using stronger language such as \"MUST filter\" instead of \"always filter\"" and its template example says "ALWAYS use this exact template structure"; the Anthropic PDF guide recommends "Use ## Important or ## Critical headers" and "Repeat key points if needed". Resolution: warn on density, not on any single use.
- **14.5 Explain why vs keep it terse.** Prompting guide and Steering blog: explain the why. CC skills page: "State what to do rather than narrating how or why". Resolution: rationale for non-obvious constraints; no tutorials.
- **14.6 Nested instruction precedence.** agents.md: "The closest AGENTS.md to the edited file wins". Claude Code: files "are concatenated into context rather than overriding each other" (closer ones read last; conflicts resolved by judgment). Codex: concatenated root-down, closer "override earlier guidance because they appear later", and `AGENTS.override.md` replaces `AGENTS.md` in the same directory. A linter should treat conflicts between levels as a finding in every case.
- **14.7 What a subagent costs at startup.** Steering blog (2026-06-18): "Name, description, and tool list at session start". Errors page counts "its name plus its `description` frontmatter" toward the 15k warning. Unverified whether `tools` is listed to the model.
- **14.8 MCP tool reference format in skills.** Platform: `ServerName:tool_name`. Claude Code tool ids and permission rules: `mcp__server__tool`. For CC-targeted skills the `mcp__` form matches what the model sees; the platform format is for the API/claude.ai environment.
- **14.9 Rules and compaction.** Steering blog table: Rules "Re-injected on compaction". Context-window doc: only unscoped rules are re-injected; `paths:` rules "reload them as Claude reads files they match" and are otherwise summarized away. The docs page is more specific; prefer it.
- **14.10 Output style context cost.** Steering blog calls it "High" in the table and "moderate context cost" in the text; features-overview: "Every request". Only the per-request fact is solid.
- **14.11 Research vs vendor advice on overviews.** Gloaguen et al. ([arXiv 2602.11988](https://arxiv.org/abs/2602.11988), Feb 2026; MemAgents @ ICLR 2026) found context files raise cost over 20% and repository overviews do not help; CC docs already say to exclude derivable layout and `/doctor` trims "directory layouts ... architecture overviews", while agents.md suggests "Project overview" as a popular section. Evidence favors CM8.

## 17. Rejected or unsourced claims

- **"CLAUDE.md has a 40K-character hard limit."** Repeated by AgentLint ("the 40K character hard limit"). Not in current docs: the hard cap is 4 MiB (file skipped), plus a startup warning whose threshold is unpublished and "now scales with the model's context window" (v2.1.169). Do not hard-code 40,000.
- **"@imports nest up to 5 hops."** Reporails thresholds doc. Docs: "maximum depth of four hops."
- **"300 lines is the CLAUDE.md limit."** Reporails. Anthropic: 200-line target; no 300 figure.
- **"CLAUDE.md is part of the system prompt."** Docs: "delivered as a user message after the system prompt". (Output styles and `--append-system-prompt` are the system-prompt routes.)
- **"MUST/NEVER/CRITICAL keywords improve compliance."** Contradicted for current models by the prompting guide; only single-line emphasis is endorsed.
- **"Order permission rules by frequency."** No source; precedence is fixed deny > ask > allow.
- **"Instruction files should include Mermaid diagrams" / "freshness markers."** No primary source.
- **"Every CLAUDE.md should include an architecture overview and directory layout."** Contradicted by CC `/doctor` behavior and by Gloaguen et al.
- **"Rules support `globs:` / `alwaysApply:` frontmatter."** That is Cursor `.mdc`; CC reads only `paths`.
- **"`@import path` syntax."** Not Claude Code; CC uses `@path`.
- **"Hook `type` is command, prompt or agent."** Outdated; `http` and `mcp_tool` also exist.
- **"Subagents nest up to five levels deep."** Steering blog (2026-06-18). The sub-agents page says: "By default, a subagent can spawn subagents of its own, up to three layers below the main conversation", adjustable with `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`. Use three as the default.
- **"Skill listing budget is 2% of context."** Outdated (v2.1.32); current docs say 1%.
- **"Skill description cap is 250 characters."** Outdated (v2.1.86); now 1,536 in CC.
- **Exact numbers for the CLAUDE.md per-file and combined startup warnings.** Not published; a linter can only reproduce the documented 200-line guidance, not CC's own trigger.

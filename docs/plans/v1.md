# rigcheck v1 — plan

## Context

The user wants a local validator for their coding-agent setup (`~/.claude` and the repos under `D:\`) in place of third-party tools like Reporails, which scores against its own rules, uploads embeddings, and false-flagged Claude Code's current memory format. The repo exists (`github.com/leftos/rigcheck`, MIT, public) with two research reports merged: `docs/research/official.md` (about 120 sourced rules from Anthropic's docs, ids like CM2, SK4, HK3) and `docs/research/sota.md` (graded non-official evidence). The main finding in the research: defect rules (silent failures, broken references, stale commands, secrets) are well supported, while prose-style rules show no measured effect on adherence. So rigcheck is a **defect and cost linter**, not a quality scorer.

Decisions already made (user): Claude Code plus AGENTS.md; checks the effective setup (repo + `~/.claude` + that project's own memory dir), with each finding tagged by layer; deterministic offline checks by default, and `--deep` for semantic checks through headless `claude -p`; findings carry fixes and rigcheck can write a fix brief but never edits files; no score, findings ranked by severity × load cost; packs `core` / `advice` / `house`; suppressions live in config and each needs a reason; token counts are offline estimates labelled ≈; rigcheck implements its own checks and the tests cross-check them against `claude plugin validate`; v1 surfaces are the CLI and a Claude Code skill.

## Architecture

Python 3.13, uv, src layout, ruff + ty + pytest + hypothesis, prek, GitHub Actions (ubuntu + windows). Runtime dependencies: `pyyaml` (frontmatter), `markdown-it-py` (code spans and fences, needed so import and path detection skips code), `jsonschema` (settings validation against a vendored SchemaStore snapshot, Apache-2.0, with attribution and a `scripts/update_schema.py` refresher).

```
src/rigcheck/
  cli.py            check | explain | brief | rules   (argparse, stdlib)
  discover.py       builds the Rig: artifacts from repo, user, plugin and memory layers
  model.py          Artifact(kind, layer, path, load_class), Finding, Rule metadata
  parse/            frontmatter.py, markdown.py (refs, imports, fences), settings.py, tokens.py
  rules/            one module per area: instructions, imports, references, rules_dir, memory,
                    skills, agents, hooks, settings, mcp, output_styles, budget, duplication,
                    secrets, advice, house
  config.py         the repo's .rigcheck.toml: suppressions
  engine.py         run rules → apply suppressions → rank
  report/           terminal.py, json.py, brief.py
  deep.py           --deep: batches files to `claude -p`, JSON output, cache by content hash
  data/             settings schema snapshot, hook events, frontmatter key tables, enums
```

- **Effective-setup discovery.** Repo layer: CLAUDE.md, CLAUDE.local.md and AGENTS.md, walking up to the repo root; nested CLAUDE.md files; `@imports` (following Claude Code's rules: skip code spans and fences, four hops); `.claude/{rules,skills,agents,commands,output-styles}`; `.claude/settings*.json`; `.mcp.json`. User layer: the same under `~/.claude`, plus `~/.claude.json` MCP entries. Plugin layer: enabled plugins' skills, agents, hooks and MCP (their findings are reported, but plugins are third-party, so they're grouped separately). Memory layer: `~/.claude/projects/<encoded path>/memory/` for this repo path only (encoding: `:`, `\` and `/` become `-`, so `D:\yaat` is `D--yaat`; checked during discovery against the real directory list).
- **Load class** per artifact: `every-turn` (CLAUDE.md chain, imports, unscoped rules, MEMORY.md head, skill/agent descriptions, active output style), `on-invoke` (skill body, subagent prompt), `on-demand` (nested CLAUDE.md, path-scoped rules, memory topic files), `config` (settings, hooks, MCP). Findings are ranked by severity, then load class, then layer (repo before user before plugin), then path.
- **Rule metadata.** Each rule has a slug id (`import-unresolved`, `hook-unknown-event`), pack, severity, `applies_to`, and evidence entries pointing into the research (`official:HK3`, `sota:#2 (A)`). `rigcheck explain <id>` prints them. A meta-test enforces that every rule has evidence and has a failing fixture and a passing fixture.
- **Outputs.** Terminal (plain ANSI, grouped by layer, with a budget table at the top), `--format json` (stable schema, for agents), `rigcheck brief -o <file>` (Markdown fix brief: findings grouped by file, each with the fix and its evidence). Exit code: 0 with no errors, 1 with errors, 2 on a usage or internal error.
- **Budget report** (not a rule): ≈tokens per every-turn source and the total; skill listing estimate against 1% of the context window; combined subagent descriptions against 15k tokens. A calibration factor comes from one real `/context` breakdown.
- **Suppressions.** `[[suppress]] rule = "…", path = "glob", reason = "…"` in `.rigcheck.toml`. A missing reason is itself a `suppression-no-reason` finding, and a suppression that matches nothing is `suppression-unused` (info).
- **Deep.** Off unless `--deep`. It lists the files it will send, calls `claude -p` with a fixed prompt per check family, parses JSON, and caches by content hash under `~/.cache/rigcheck`. The exact flags (`--output-format json`, any schema flag) are checked against `claude --help` when this milestone is built.

- **core, warn (added with docs discovery):** `skill-dispatch-agent-missing`: a skill's prose dispatches an agent by a name no built-in or custom subagent has ("dispatch `X`" ending a clause, "`X` agent" or "`X` subagent", `subagent_type: "X"`; fenced blocks and frontmatter are not read; evidence `rigcheck:agent-refs`, `rigcheck:builtin-tables-probe`). `reference-path-missing` also scans repo docs, skills, agents and commands, where it skips single-segment tokens, tokens with `(`, and `:<symbol>` or `:<n>-<m>` suffixes, and accepts a `../` path that exists outside the repo; `<!-- rigcheck: allow reference-path-missing -->` silences its line and the next.
- **core, suppressions:** `suppression-no-reason` (warn, shipped): a `.rigcheck.toml` entry with a missing, empty or whitespace reason; `suppression-unused` (info): an entry that matched no finding ([rules/suppressions.md](../rules/suppressions.md)).
- **advice, info only, each citing the doc and the null result:** over 200 lines (CM1); prose pointer instead of an import (CM4); tree or dependency dumps (CM8); long procedures in CLAUDE.md (CM9); must-happen rules better written as a hook (CM10); emphasis density (CM11, PR4); unstructured walls of text (CM12); generic rule filenames (RL5); skill description not in third person (SK6); SKILL.md over 500 lines (SK9); no table of contents in a long reference file (SK12); backslash paths (SK13); time-sensitive text (SK14); side-effect skill that Claude can invoke (SK18); read-only-sounding agent with write tools (AG10); memory index shape (MM2); reasoning-extraction phrasing (PR10).
- **deep (`--deep`):** vague directives (CM6), contradictions across the loaded set (CM7), paraphrased duplicates, whether a skill description says what and when (SK5), agent prompts that assume main-session context (AG7), `context: fork` with no task (SK20), bare emphasized prohibitions (PR2).
- **house (off by default, generic, configurable):** hard-wrapped Markdown; coined-terms glossary exists and is linked from the docs start page; agent files with `tools:` include configured tools (for example `SendMessage`); agent files carry configured sections (for example a `## Boundaries` section).
- **Not encoded (sota §6):** instruction-count budgets, line caps as errors, position, polarity, specificity scores, examples vs rules, corpus quality bands, required overview or tech-stack sections.

## Verification

- Per rule: a failing fixture and a passing fixture under `tests/fixtures/<rule-id>/` (the meta-test enforces this); hypothesis property tests for the frontmatter and import parsers (fences and code spans never produce imports; parsing never crashes on arbitrary text).
- Cross-check: a test that runs `claude plugin validate` on the skill and agent fixtures when `claude` is on PATH, asserting it agrees wherever both tools check the same thing (skipped in CI).
- Real rigs: `rigcheck check D:\yaat` must report the AGENTS.md/CLAUDE.md `dotnet format` near-duplicate (the home target has no repo chain, so `rigcheck check ~` cannot); both must not flag `metadata.type` memory files, and must finish in a few seconds without `--deep`. The budget table is compared once against `/context` on the same session to set and record the calibration factor.
- Calibration, measured 2026-09-27 against `/context all` in a fresh D:\yaat session with no prompt (Opus 5.5, 1M window): Memory files 27.1k against rigcheck's ≈18.0k at 3.8 chars/token (root CLAUDE.md 10.1k + user CLAUDE.md 7.7k + MEMORY.md 0.2k), a factor of 1.51 (1.40 if the shadowed AGENTS.md, ≈1.4k, also loads; `/context` does not list the files); ten user agents' name + description 67–736 tokens against ≈50–588, a mean factor of 1.25 (a fit gives ≈3.0 chars/token); skills 9.9k, exactly 1.0% of the window, so the listing sat at its cap. So instruction files are estimated at 2.5 chars/token and descriptions at 3.0.
- Suite runs at below-normal priority (`nice -n 10 uv run pytest`); ruff and ty clean; CI green on ubuntu and windows before each merge.
